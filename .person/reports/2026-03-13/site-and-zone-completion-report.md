# Site & Zone 도메인 기능 구현 및 버그 수정 완료 보고서

## 1. 작업 개요
- **작업명**: 구역(Zone) 및 사이트(Site) 관리자 CRUD, 고객 예약 필터링 구현 및 시스템 안정성 확보
- **일시**: 2026-03-13
- **목적**: Phase 2의 핵심 과업인 사이트 관리 기능과 날짜 기반 예약 가능 사이트 조회 기능을 완성하고, 초기 발생한 시스템 구동 및 실행 오류를 해결함.

## 2. 변경 및 수정 사항

### 2.1 Admin CRUD 및 고객 필터링 구현
- **관리자 기능**: 구역(Zone) 및 사이트(Site)의 생성, 목록 조회, 삭제 기능을 전용 컨트롤러(`AdminSiteController`)로 분리 및 구현.
- **가용성 조회**: `ReservationRepository`의 `@Query`를 활용하여 예약된 사이트를 제외한 실시간 가용 사이트 필터링 구현.
- **DTO 개선**: `SiteResponse.ListDTO`에 `maxPeople` 필드를 추가하여 뷰 데이터 정합성 확보.

### 2.2 시스템 안정성 및 버그 수정
- **매핑 중복(Ambiguous Mapping) 해결**: 
    - `AdminController`, `UserController`, `AuthController` 간의 중복된 URL 매핑(예: `/admin/users`, `/login-form`)을 정리하여 애플리케이션 기동 오류 해결.
- **데이터 삽입 오류 해결**: 
    - `ErpApplication`에 `@EnableJpaAuditing`을 추가하여 엔티티 저장 시 `created_at` 누락으로 인한 DB 제약 조건 위반 해결.
    - `AdminSiteController`에서 실수로 누락된 `saveSite` 메서드 복구.
- **데이터 페칭(Fetching) 최적화**: 
    - `SiteRepository`에 `join fetch`를 사용하는 `findAllWithZone` 메서드를 도입하여 지연 로딩 문제를 해결하고 모든 데이터가 화면에 정확히 출력되도록 수정.
- **참조 무결성 예외 처리**: 
    - `GlobalExceptionHandler`에 `DataIntegrityViolationException` 핸들러를 추가하여, 예약 내역이 있는 사이트 삭제 시 에러 페이지 대신 "삭제 불가" 안내 Alert와 리다이렉트가 동작하도록 구현.

## 3. 검증 결과
- **서버 기동**: 중복 매핑 제거 후 정상 구동 확인 (Started ErpApplication).
- **CRUD 테스트**: 구역 및 사이트의 생성과 삭제(참조가 없는 경우)가 정상적으로 처리됨을 확인.
- **필터링 테스트**: 날짜 및 인원수에 따른 사이트 목록의 동적 변화 확인.
- **예외 처리**: 예약 내역이 있는 사이트 삭제 시도 시 사용자 알림창이 정상적으로 작동함을 확인.

## 4. 비유로 설명하는 작업 내용
이번 작업은 마치 **"캠핑장 관리 시스템의 설계도를 완성하고, 전선이 꼬인 부분을 모두 풀어낸 것"**과 같습니다.
처음에는 관리용 전등 스위치가 여러 개여서(중복 매핑) 전원을 켤 수 없었지만, 이를 하나로 정리해 불을 밝힐 수 있게 되었습니다. 또한, 장부에 날짜를 적지 않아 발생하던 기록 오류(Auditing 미설정)를 해결하고, 장부의 내용이 한눈에 보이도록(Join Fetch) 정리했습니다. 마지막으로, 손님이 예약 중인 자리를 억지로 치우려 할 때(참조 무결성 위반) 시스템이 "이곳은 현재 이용 중입니다"라고 정중히 안내하도록 안전 장치도 마련했습니다. 이제 캠핑장 운영을 위한 튼튼한 기틀이 마련되었습니다!

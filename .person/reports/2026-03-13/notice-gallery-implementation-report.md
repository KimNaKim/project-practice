# 📢 공지사항 및 갤러리 도메인 구현 및 디버깅 보고서

## 1. 작업 요약
- **목적**: Phase 2의 독립 도메인(Notice, Gallery) 백엔드 로직 완성 및 데이터 바인딩.
- **기간**: 2026-03-13 (최종 수정 및 검증 완료)

## 2. 주요 변경 사항

### 2.1 공지사항 (Notice)
- **엔티티 고도화**: `category`, `viewCount` 필드 추가 및 `NoticeCategory`(Enum) 적용.
- **CRUD 구현**: 관리자 전용 등록/수정/삭제 기능 및 사용자용 목록/상세 페이지 구현.
- **데이터 바인딩**: 더미 데이터를 제거하고 실제 DB 연동 (조회수 증가 로직 포함).

### 2.2 포토 갤러리 (Gallery) & 이미지 (Image)
- **다중 이미지 시스템**: `ImageService`를 통한 파일 업로드(UUID 관리) 및 `Gallery`와의 1:N 연관관계(`CascadeType.ALL`) 구축.
- **리소스 매핑**: `WebMvcConfig` 설정을 통해 `./uploads` 경로의 파일을 `/upload/**` URL로 서빙.
- **최적화**: N+1 문제 방지를 위해 `findAllWithImages()` 페치 조인(Fetch Join) 적용.

## 3. 트러블슈팅 및 해결 (Troubleshooting)

### 3.1 Ambiguous Mapping 오류
- **문제**: `AdminController`와 도메인별 `AdminController` 간 URL 중복 매핑 발생.
- **해결**: `AdminController`에서 중복된 공지사항/갤러리 매핑을 제거하고 도메인 컨트롤러로 일원화.

### 3.2 SQL 초기화 오류 (DbException)
- **문제**: 엔티티 스키마 변경(`category`, `viewCount` 추가) 후 `data.sql`의 기존 INSERT 문이 구조와 맞지 않아 서버 기동 실패.
- **해결**: `data.sql`의 `notice_tb` 인서트 문을 새로운 컬럼 구조에 맞게 수정.

### 3.3 404 Not Found 및 데이터 미출력
- **문제**: 컨트롤러에 `@Controller` 어노테이션 누락 및 템플릿에 더미 데이터 잔존.
- **해결**: 모든 컨트롤러에 어노테이션 추가 및 템플릿의 `{{#galleries}}` 바인딩 로직 정상화.

## 4. 기술적 설명 (비유로 설명)

### 🛠️ 페치 조인(Fetch Join): "한 번에 다 가져오기"
데이터를 가져오는 것은 **마트 장보기**와 같습니다.
- **일반 조회**: 사과(갤러리)를 사고 집에 왔는데, 사과 포장지(이미지)가 없어서 다시 마트에 가는 번거로움(Lazy Loading)이 생깁니다.
- **페치 조인**: 처음부터 사과와 포장지를 한 바구니에 담아 한꺼번에 계산하고 가져오는 것입니다. 덕분에 마트를 여러 번 왔다 갔다 할 필요 없이 효율적으로 정보를 보여줄 수 있습니다.

## 5. 최종 검증 결과
- 공지사항 상세 조회 시 조회수 정상 증가 확인.
- 관리자 페이지에서 다중 이미지 포함 갤러리 게시글 등록/수정/삭제 정상 동작 확인.
- 메인 페이지 및 헤더 링크를 통한 페이지 전환 무결성 검증 완료.
